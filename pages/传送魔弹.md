涉及位移的法术，能够影响施法者，目标或两者。   
  
**传送魔弹** 是一种投射物法术，能射出一个白色的投射物，在失效时尝试将玩家传送过去。 

**小传送魔弹** 是它的小型版本，蓝耗更低，发射的投射物存在时间更短、速度更快。 

社区常常把这两者合称**传送魔弹** 或**tp** ，并且为了区分，通常会把传送魔弹称呼为**大传送魔弹** 、**大传** 或大**tp** ，而把小传送魔弹称呼为**小传** 或**小tp** 。交流时请注意根据语境进行辨别。 

## 使用技巧

  * 学会使用它们能够极大提升玩家的机动性，帮助你躲避弹幕、敌人和各种危险，在[长线流程](长线攻略.md)中，它们也能显著提高跑图效率，是非常有用的法术。
  * 小传送魔弹往往比大传送魔弹更好用，因为它蓝耗更低、速度更快且存在时间更短。这意味着它不容易飞得太远以至于把你传送到缺乏视野的危险区域，而且使你在面临危险时只需要很少的等待时间就能传送走。 
    * 为了弥补大传送魔弹的这些缺陷，使用它的时候可以尽量朝墙上射击。
  * 它们在进行传送前会检查目的地是否在加载区块内、是否有足够的空间容纳玩家，如果不在加载区块内或空间不足，传送将会失败。这意味着它们不会把你传送到墙里。 
    * 但是它们有可能将你传过较薄的天花板，并且不一定能把你再传送下去，请小心行事。
  * 在竖直方向上移动时使用它们代替飞行可以有效节约浮空能量，从而使你能更加从容地保持在空中。
  * 使用它们可以方便地避开圣山的坍塌判定区域（见[画廊](#画廊)），从而避免圣山坍塌，保留其编辑魔杖的功能。
  * 小传送魔弹的速度已经达到了 1000 像素/秒的[速度上限](速度.md)，为它添加加速修正无法进一步加快它的速度。


  * 直接把它们做成[机枪](基础攻略：机枪杖.md)可能不是好主意，由于相机和玩家的运动存在时间差，过快的射速往往会导致你沿着一个“之”字型的轨迹往返传送。更多细节参见[专家攻略：传送魔杖](https://noita.wiki.gg/zh/wiki/%E4%B8%93%E5%AE%B6%E6%94%BB%E7%95%A5%EF%BC%9A%E4%BC%A0%E9%80%81%E9%AD%94%E6%9D%96%3Faction%3Dedit%26redlink%3D1)。 
    * 对于大传送魔弹，等待它失效后再发射下一发即可；对于小传送魔弹，两次发射的间隔略大于 0.2 秒能获得非常良好的连续传送体验。
    * 如果你想把它们制作成机枪，通过[零时](零时.md)或[缩减存在时间](缩减存在时间.md)（红表）减少它们的存在时间可以有效避免“之”字型传送，并且允许你以更高的速度传送。但需要注意的是单个红表可能使大传送魔弹[永久化](专家攻略：无限持续时间法术.md)，导致产生不想要的效果。

## 传送跃迁

传送类法术依赖一个名为`TeleportProjectileComponent`的组件，以下法术使用了这个组件： 

[传送魔弹](##)[传送魔弹](##)[返回](返回.md)  
---  
  
这个组件会检查目的地是否位于加载区块中，所以上述法术正常情况下不能用于[跃迁配置](专家攻略：跃迁配置%2F超传配置.md)，因为跃迁需要把玩家传送到远方的未加载区块中。 

然而，这个组件的实现存在一个bug，会使得游戏误认为远方的未加载区块是加载的，这就为传送跃迁的实现提供了可能，下文将给出实现条件与原理解析。 

### 传送跃迁是在什么位置会生效

先说结论，要让以上法术在未加载区块进行传送，需要满足以下两点条件： 

1.设已加载区块的坐标为 a ，在未加载区块的可生效坐标为 b ， a 和 b 可以是 x 坐标或 y 坐标： 

b=a+131072n (n∈Z,n≠0)

2.可生效坐标对应的已加载区块坐标位置不能被地形阻挡。 

这使得这类配置只能跃迁大约 131072n 像素的距离，可调节性和精度都非常差，基本无实用性。 

  * 131072 像素对于 NG 来说是 3.66 个平行世界，所以这类配置难以做到精准跃迁到 NG 平行世界的对应位置；不过，这个距离对于 [NG+](NG+.md) 来说刚好是 4 个平行世界，这可能是这类配置唯一值得说道的地方。
  * 而且 131072 像素恰好也是半个镜像世界的大小，这会导致[很多问题](专家攻略：如何理解跃迁魔杖.md)，比如跃迁后游戏崩溃等。

### 传送跃迁的原理

原理是`TeleportProjectileSystem`在判断区块是否加载时存在漏洞，这个漏洞有点像**[镜像世界](镜像世界.md)** 的一个漏洞，都是关于错误判断未加载区块的漏洞。 

话虽如此，实际上这两个漏洞几乎一模一样，只是有些许差别，我们先从游戏的网格地图实现细节和镜像世界的错误判断未加载区块漏洞开始说起。 

游戏将地图中的材料称为`Cell`[[2]](#cite_note-2)，一个区块是由 512x512 个单元组成的。 

然后游戏中每个区块都属于一个更大的结构，我们在这里称其为区域[[3]](#cite_note-3)，一个区域将包含 512x512 个区块。 

相关伪代码结构如下： 
    
    
    typedef struct Cell (*cell_array)[0x40000];
    struct ChunkMap {
        int unknown[2];
        cell_array* (*cells)[0x40000];
        int unknown2[8];
    };
    struct GridWorld {
        struct GridWorld_vtable* vtable;
        int unknown[318];
        int world_update_count;
        struct ChunkMap chunk_map;//+1280
        int unknown2[41];
        struct GridWorldThreadImpl* mThreadImpl;
    };
    

这里面的`ChunkMap::cells`就是区域的定义。而游戏在运行中只会有一个GridWorld的实例，这使得区域是单例实现的。 

由于单例的问题，这导致游戏不能有两个活跃的区域被加载，这就是镜像世界的原理之一。 

这是游戏判断区块是否加载的伪代码： 
    
    
    bool __thiscall is_chunk_loaded(ChunkMap* this, int x, int y){
        uint16_t offset_x = (uint16_t)(x >> 9);// >> 9 类似 / 512
        offset_x -= 256;
        offset_x &= 0x1FF;
    
        uint16_t offset_y = (uint16_t)(y >> 9);
        offset_y -= 256;
        offset_y &= 0x1FF;
        offset_y *= 512;
        return *this->cells[offset_x + offset_y];
    }
    

可以看到游戏通过`x &= 0x1FF`的形式，屏蔽了大于等于 512 的计算结果防止越界。 

通过以上代码来确定坐标对应的区块，如果区块未加载，那么解引用出来的是空指针 0 ，而 0 代表 false ，游戏认为区块并不处于加载状态。 

反之有区块则不是空指针，那么游戏就认为区块处于加载状态。 

你有发现什么问题吗？nolla完全没有检查坐标是否超出了当前的区域，这使得如果一个坐标过大，那么因为`x &= 0x1FF`，计算结果就会发生**绕回** 现象， 

而0x1FF是 511 ，这让数字限制是 0~511 ，即可以表达 512 个数，那么我们可以算出如果要让计算结果绕回原地的坐标数值是512×512=262144[[4]](#cite_note-4)。 

这个就是镜像世界的错误判断未加载区块的漏洞，但是我们可以发现，这个漏洞要求是间隔 262144 而非 131072 ，那么`TeleportProjectileSystem`的bug又是怎么回事呢？ 

这是`TeleportProjectileSystem`进行更新时关于区块加载判断的伪代码： 
    
    
    //Projectile.x和Projectile.y为float
    void __thiscall TeleportProjectileSystemUpdate(TPSystem* this, Entity& Projectile, unknown& unknownObj){
        int x = (int)Projectile.x - 16;
        int y = (int)Projectile.y - 16;
        bool is_chunk_loaded = *unknownObj.field1[(uint8_t)(x >> 9) + ((uint8_t)(y >> 9) << 8)]
    }
    

实际上有关于unknownObj是什么，目前是未知的，但是逻辑是类似的，这段代码通过将类型转换为uint8_t隐式的限制了坐标大小。 

而uint8_t可以表达256个数，那么我们可以算出如果要让计算结果绕回原地的坐标数值是256×512=131072

这就是传送魔弹只需要间隔 131072 而不是 262144 的原因。
